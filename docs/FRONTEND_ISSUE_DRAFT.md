> 后端 Issue，也不表示下列能力已经实现。当前已实现范围以

## 1. 发布和拆分规则

### 1.1 标题、GitHub Type 与优先级

```text
[Feature] 前端/页面或工作流 - 用户可见能力
[Quality] 前端/场景 - 可访问性、契约、权限、测试或韧性验证
[Delivery] 前端/交付物 - 演示、截图、操作说明或发布材料
```

| 草案前缀 | GitHub Type | 默认 Label |
| --- | --- | --- |
| `[Feature]` | `Feature` | `enhancement`、`frontend` |
| `[Quality]` | `Task` | `frontend`；涉及文档时另使用 `documentation` |
| `[Delivery]` | `Task` | `documentation`、`frontend` |

除 `frontend` 外不新建 `area:frontend`、`client:family`、`p0` 等自定义 Label。`frontend` 是
本草案每条 Issue 必带的端别 Label；与总草案 `#2`–`#67` 的 `backend` 成对使用，二者均不替代
GitHub 原生 Type、Priority 或官方 Label。模块、依赖、隐私等级和测试要求写在 Issue 正文。
优先级映射与总草案一致：P0 → GitHub `High`，P1 → `Medium`，P2 → `Low`；只在真实阻断发生后
使用 `Urgent`。

### 1.2 前端边界

- React Router 的路由守卫、隐藏按钮和 UI 文案只改善使用体验，**不是权限控制**；每次
  读取和写入仍须由服务端按认证、案件成员关系和字段裁剪重新判定。
- 前端只保存当前标签页所需的 Bearer token（现有实现使用 `sessionStorage`）。不得把 token、
  密码、完整病史、精确轨迹、原始聊天、附件原文或第三方密钥写入 `localStorage`、URL、
  遥测、截图、控制台日志或错误上报。
- AI 产生的内容必须呈现来源范围、生成时间、`草稿/待审核/已发布` 状态和人工确认入口；
  前端不得把模型建议渲染为已确认事实、自动发布内容或自动派遣任务。
- 位置采集必须显示任务关联、采集状态、开始/暂停/停止入口和最小必要精度；任务结束、退出
  或权限失效后必须停止采集。地图服务失败时保留文字任务、静态点位或人工联络降级。
- 本轮所有新增页面沿用 `frontend/` 的 React + TypeScript + Vite、HeroUI 3、Tailwind CSS 4
  和 Lucide React，不为单页另建 UI 框架或平行 API client。

### 1.3 每条前端 Issue 的完成定义

除另有说明外，每条 Feature / Quality Issue 关闭前均满足：

- API 调用、请求/响应类型和错误处理与 `docs/openapi.yaml` 对齐；尚未落地的 API 必须明确
  标注依赖，不能用猜测的路径或字段伪造“已接通”。
- 至少覆盖加载、空数据、成功、失败、无权限/会话失效和窄屏（最小 320px）状态；异步提交
  防止重复提交，并向屏幕阅读器提供可感知反馈。
- 可交互元素具备可见焦点、正确名称和键盘操作；颜色不是状态的唯一表达。敏感操作、发布、
  位置开始和不可逆状态变更须有明确确认。
- 不以客户端角色判断替代服务端授权。遇到 `401` 清除本地会话并回到登录；遇到 `403` / `404`
  使用不泄露资源存在性的通用提示；网络和第三方服务失败提供重试或明确的人工降级。
- 有与改动相称的单元、组件或浏览器 E2E 证据；`npm run lint:frontend` 与
  `npm run build:frontend` 通过。若引入 E2E 工具，应在同一 Issue 中增加可复现命令。

## 3. 认证、壳层与通用交互

### FE-01 `[Feature] 认证入口 - 登录、会话恢复、退出与失效反馈`

- **字段**：`Priority=P0 - 初赛必需`；`Sprint=Day 1-3`；`Estimate=0.5d`；`Demo Step=基础设施`。
- **关联**：总草案 `A-01`；`POST /api/auth/login`、`GET /api/auth/me`、`POST /api/auth/logout`。
- **内容**：完善当前登录页和认证上下文的提交状态、通用错误语义、会话恢复、退出和过期回退。
  后端对账号枚举和限流的语义必须原样保留，前端不自行区分“账号不存在”与“密码错误”。
- **验收标准**：有效账号可进入对应角色主页；登录中禁止重复提交；失败内容不暴露账号存在性、
  密码或 token；刷新后仅通过 `/auth/me` 恢复会话；退出本地会话前尝试服务端撤销；网络异常或
  会话失效时提供安全的重新登录入口。

### FE-02 `[Feature] 应用壳层 - 角色导航、页面标题与安全状态反馈`

- **字段**：`Priority=P0 - 初赛必需`；`Sprint=Day 1-3`；`Estimate=0.75d`；`Demo Step=基础设施`。
- **关联**：总草案 `A-01`、`I-03`；现有 `AppShell` 与响应式底部导航。
- **内容**：将三端和后续学习/管理入口收敛到一份声明式导航配置，补齐当前角色、服务状态、
  页面标题、未授权、找不到页面和移动端安全区体验。
- **验收标准**：桌面侧栏与移动底部导航只展示当前角色应使用的入口；当前路由有文字和非颜色

  遮挡表单提交按钮或重要状态。

### FE-03 `[Quality] API Client、错误边界与前后端类型契约`

- **字段**：`Priority=P0 - 初赛必需`；`Sprint=Day 1-3`；`Estimate=1d`；`Demo Step=基础设施`。
- **关联**：总草案 `I-03`；`frontend/src/api/client.ts`、`docs/openapi.yaml`。
- **内容**：统一 API client 的超时/取消策略、错误对象、认证失效处理、查询刷新和 TypeScript
  数据模型；为后续 API 增加一份可审查的端点—类型—页面映射。
- **验收标准**：请求不会静默吞掉失败；并发页面卸载后不写入过期状态；服务返回空响应、非 JSON

  OpenAPI 字段不靠 `any` 绕过；认证失败不会反复重试或泄露受保护页面缓存。

  错误组件，避免各业务页各自解释失败。
- **验收标准**：异步数据不以空白页面代替加载；错误可重试且保留安全的上下文；成功/失败消息

## 4. 家属端：问询、确认与公开进展

### FE-05 `[Feature] 家属端 - 引导问询与可恢复的答案草稿`

- **验收标准**：家属可创建、继续并提交问询；提交中禁止重复写入；服务端指出缺项时能定位到
  对应问题；AI 不可用时显示后端提供的规则化问题，不伪造 AI 回复；离开前仅提示未提交内容，
  不将敏感答案写入 URL、日志或跨设备持久化存储。

### FE-06 `[Feature] 家属端 - 老人画像草稿确认、修订与建案结果`

  为真实状态；无权访问会话时不显示草稿内容。

  扫描中和拒绝状态清楚可见；不在缩略图、文件名或前端日志中额外泄露敏感信息。

### FE-08 `[Feature] 家属端 - 公开案件进展、防走失知识与线索补充`

  范围、来源和失败提示；外部地图加载失败、离线或无配额时，仍可通过文字点位和任务说明完成
  Demo；不呈现“预测位置”或确定性搜救结论。

### FE-14 `[Feature] 指挥端 - 公共案情板与 AI 摘要发布审核`

- **关联**：总草案 `G-01`、`G-02`、`G-03`、`G-04`；依赖摘要和摘要草稿 API。
- **内容**：建立面向指挥的摘要草稿审核与发布页，区分内部可见内容、家属公开进展和志愿者
  必要任务摘要。
- **验收标准**：每份草稿显示来源范围、生成时间、版本、审核状态与不确定项；发布前明确显示
  目标受众和将公开的字段；未审核草稿永不出现在公共案情板；服务失败时保留后端确定性摘要
  或人工编辑草稿；发布结果以服务端返回版本为准。

## 6. 志愿者端：本人任务、导航、位置与反馈

### FE-15 `[Feature] 志愿者端 - 我的任务、状态推进与线索反馈`

  并将任务结果/线索反馈送入人工审核。
- **验收标准**：志愿者只看到 `/tasks/mine` 返回的数据，不在 DOM、缓存或错误信息中保留其他
  人任务；开始、暂停、完成和反馈遵循服务端状态机；线索反馈显示待审核而非自动确认；无任务、
  过期任务和权限失效有明确提示；窄屏下单手操作不遮挡“停止任务”入口。

### FE-16 `[Feature] 志愿者端 - 任务导航、安全提示与第三方服务降级`

- **字段**：`Priority=P0 - 初赛必需`；`Sprint=Day 8-11`；`Estimate=1d`；`Demo Step=志愿者执行`。
- **关联**：总草案 `E-08`、`F-03`、`F-04`、`F-06`；依赖导航、天气/路况与安全提示 API。
- **内容**：提供任务绑定的导航入口、路线文字摘要、出发前安全确认与天气/路况降级说明。
- **验收标准**：打开外部导航前显示目的地范围与离开工作台的提示；无法获得导航或条件服务时
  显示文字路线、人工联络和“不要擅自进入高风险区域”提醒；安全提示可阅读但不能被前端静默
  跳过；外部链接不携带 token、完整病史或不必要身份信息。

### FE-17 `[Feature] 志愿者端 - 任务内模拟位置上报与显式停止`

- **关联**：总草案 `E-06`、`E-09`、`E-11`；依赖任务位置上报 API。
- **内容**：在获得任务、告知和用户操作后，提供模拟位置上报控件及状态面板；第一阶段只使用
  受控模拟坐标/静态轨迹，不接入后台持续定位。
- **验收标准**：上报前明确显示任务、用途、精度/频率和停止条件；开始、暂停、停止状态可见；
  任务完成、切换任务、退出登录、权限失败和页面卸载时停止定时上报；不展示其他志愿者完整
  轨迹；服务拒绝过期/异常点位时保留可操作的错误和人工联络降级。

## 7. 学习、归档与管理端

### FE-18 `[Feature] 学习中心 - 手册、脱敏案例与新人问答入口`

- **内容**：提供不依赖案件权限的学习入口，展示经审核的手册、脱敏案例、来源和更新日期，并为

- **验收标准**：学习页不以培训名义读取真实案件数据；问答引用的知识来源、局限和审核状态
  可见；回答不确定时提示人工核验；提交内容不被渲染为 HTML；资源为空和问答服务失败都有

### FE-19 `[Feature] 管理端 - 模拟归档、脱敏确认与案例发布`

- **字段**：`Priority=P1 - 演示增强`；`Sprint=Day 12-15`；`Estimate=1.5d`；`Demo Step=案例归档`。

- **验收标准**：页面显著标为“模拟、脱敏数据”；原始内容与脱敏预览分栏且访问受控；未经

  敏感日志。

## 10. 发布前需要确认的产品决策

   重置方式和 CI 命令。
