# Demo 与初赛交付

## 1. Demo 原则

演示的重点是让评委看到“信息如何从混乱变得可审核、任务如何在地图上闭环、人员安全如何被保护”，而不是展示未经验证的自动决策。

所有演示材料必须使用虚构或充分脱敏的数据，并在界面、视频和讲解中说明这是模拟案件。AI 输出要展示草稿、审核和状态变化，不能剪掉人工确认步骤。

## 2. 建议故事线

1. 家属进入家属端，选择“老人走失求助”，上传合规的模拟照片和基本信息。
2. AI 问询助手继续询问病史、行动能力、常去地点、最后出现地点、随身物品和交通习惯。
3. 系统生成老人画像草稿；家属或指挥人员确认后进入案件。
4. 指挥端展示第一版案情，明确已确认信息、待核实线索和缺失项。
5. 地图展示最后出现点、常去地点及附近医院、派出所、公交站、市场等 POI。
6. 指挥人员创建“核实公园北门至菜市场路线”任务并分配给志愿者 A。
7. 志愿者端仅收到本人任务，查看天气/安全提醒并打开导航。
8. 志愿者开始任务后回传模拟位置，到达后上传照片和文字反馈。
9. 新反馈先进入待审核区；指挥人员确认后，地图、线索时间轴和案情摘要刷新。
10. 案件模拟结束，后台导入虚构聊天记录，完成脱敏和人工审核后生成复盘案例与题目。

## 3. 演示数据包

建议包含：

- 一例模拟案件及案件代号；
- 一张具有合法使用权的模拟老人照片；
- 基础画像、最后出现点、常去地点和若干 POI；
- 至少一条已确认、一条待核实、一条已排除线索；
- 两项任务及不同状态；
- 一段模拟志愿者轨迹；
- 一份虚构群聊记录；
- 一份简版搜救手册和两到五道题目；
- 家属、指挥、志愿者、新人四类演示账号。

数据包中不得存在真实电话、身份证号、家庭住址、未授权照片、真实群聊或可关联真实案件的细节。

## 4. 初赛交付物

| 交付物 | 最低要求 |
| --- | --- |
| 可访问 Demo | 三端原型，至少完整跑通一例模拟案件；失败时有录屏兜底 |
| 演示视频 | 3–5 分钟，说明痛点、闭环、AI、地图、安全和公益价值 |
| 项目计划书 | 痛点、产品范围、技术路线、数据治理、风险和迭代计划 |
| 演示账号 | 家属、指挥、志愿者、新人四种最小权限账号 |
| 样例数据包 | 脱敏模拟案件、聊天、地图点位、任务、轨迹和知识文本 |
| 路演 PPT | 建议 10 页以内，突出真实场景、可见变化、阿里生态和可持续性 |

## 5. 五项核心能力验收

### 5.1 家属问询与画像

- 缺少关键内容时能够继续追问。
- 画像明确标记为 AI 草稿。
- 用户可修改或拒绝内容。
- 敏感信息不会进入无权限视图。

### 5.2 指挥端案情总结

- 区分已确认、待核实和已排除信息。
- 显示生成时间、输入范围和审核状态。
- 新线索只有审核后才改变正式案情。

### 5.3 地图态势

- 显示最后出现点、线索点、任务点、POI 和模拟轨迹。
- 不同角色看到的位置精度和内容不同。
- 地图服务失败时仍可查看文字任务和坐标描述。

### 5.4 志愿者任务闭环

- 只能访问本人任务和必要案情。
- 定位只在任务期间开启且状态可见。
- 能提交反馈，并进入待审核流程。
- 能展示超时、天气或区域风险提醒中的至少一种。

### 5.5 案例经验库

- 原始模拟记录经过脱敏和人工确认。
- 生成时间线、经验点和题目候选。
- 知识问答带来源，无依据时不编造。

## 6. 演示检查清单

演示前：

- 固定演示数据和账号，重置到已知状态。
- 确认 AI、地图、对象存储的密钥、配额和网络。
- 关闭调试信息、真实账号通知和无关后台入口。
- 检查所有截图、浏览器历史、日志和地图标注无真实隐私。
- 准备离线视频、静态地图和人工摘要作为降级方案。

演示后：

- 撤销临时公开地址和演示密钥。
- 删除评委输入或测试上传中的意外个人信息。
- 保留非敏感的故障记录与改进项。
- 如需公开录像，再次检查画面、字幕、控制台和链接。

## 7. 暂不宣称的能力

在没有实现证据和验证报告前，路演材料不得宣称：

- 已与警方、医院、社区或正式救援组织建立系统对接；
- 已在真实案件中证明提高找回率；
- AI 能准确预测老人位置或自动制定安全搜救方案；
- 已完成生产级合规、安全审计或大规模并发验证；
- 具备人脸识别、监控接入或跨平台追踪能力。
