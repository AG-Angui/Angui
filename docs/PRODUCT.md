# 产品范围

## 1. 项目定义

安归是一套面向失智老人走失搜救的 AI + 地图协同系统。它通过家属端、指挥端和志愿者端，把零散信息整理为可审核的线索，把经确认的任务落实到地图和人员，并把行动过程沉淀为经过脱敏的案例经验。

产品核心表达是：

> AI 帮助“问清楚、理清楚、讲清楚”，地图帮助“看得见、走得到、守得住”。

系统只提供信息采集、辅助分析、协同和学习能力，不替代警方、消防、医疗、专业救援组织或现场指挥人员。

## 2. 目标与成功标准

MVP 的目标不是覆盖完整真实搜救业务，而是用一例脱敏模拟案件证明三端协作闭环成立。

首阶段成功标准：

1. 家属能够通过引导问询补齐关键信息，并确认 AI 整理的老人画像。
2. 指挥人员能够区分未核实、已确认、已排除的线索，生成带更新时间和来源范围的案情摘要。
3. 地图能够呈现模拟案件中的关键点位、任务、POI 和志愿者轨迹。
4. 志愿者只能看到完成本人任务所需的信息，能够上报位置和反馈线索。
5. 案件资料能够在脱敏、审核后形成复盘案例和学习素材。
6. 全流程能展示人工确认、最小权限、审计留痕和 AI 不确定性。

## 3. 用户与核心需求

### 3.1 家属或知情人

- 在焦虑状态下仍能按步骤提交必要信息。
- 知道哪些信息缺失、哪些内容已经确认。
- 能持续补充文字、时间、地点和图片线索。
- 只能看到适合公开的进展，避免内部调度和个人位置泄露。

### 3.2 指挥人员

- 汇总来自家属、电话、聊天和现场反馈的碎片信息。
- 审核 AI 提取结果，维护统一的线索状态和公共案情。
- 在地图上组织任务并观察人员安全态势。
- 对关键操作进行确认、追踪和复盘。

### 3.3 志愿者

- 获得最新且与本人相关的任务、路线和安全提示。
- 方便地回传位置、照片、文字和任务结果。
- 避免接触无关敏感信息或未经证实的猜测。
- 在超时、失联、偏离任务区或进入风险区域前收到提醒。

### 3.4 新人志愿者

- 通过手册、脱敏案例、题库和知识问答了解基本流程。
- 在未获得真实案件权限前，使用模拟环境完成学习。

## 4. MVP 功能范围

| 模块 | MVP 必需能力 | 后续候选能力 |
| --- | --- | --- |
| 家属端 | 引导问询、照片/地点提交、老人画像确认、线索补充 | 预建档、防走失设备接入 |
| 指挥端 | 案件、线索时间轴、审核、案情摘要、任务看板、地图态势 | 多组织协作、复杂资源调度 |
| 志愿者端 | 本人任务、导航入口、位置上报、轨迹、提醒、线索反馈 | 离线地图、弱网同步、穿戴设备 |
| 学习中心 | 队伍介绍、搜救手册、案例和题库雏形 | 学习进度、考核与认证 |
| 案例经验库 | 模拟聊天导入、脱敏、摘要、经验标签、检索 | 跨组织知识治理与质量评估 |

## 5. 核心业务流程

### 5.1 信息采集与画像

家属提交基础信息后，问询助手按基本信息、身体状况、行为习惯、最后出现、常去地点、可能动机、随身物品和后续线索逐步追问。AI 生成的画像必须标记为草稿，由提交人或指挥人员确认后才能进入案件正式视图。

### 5.2 线索审核与案情更新

所有新输入先成为“待审核信息”。AI 可以提取时间、地点、人物、内容和建议动作，但不能自行改变事实状态。指挥人员审核后，线索才可变为已确认、待核实、已排除或已失效，并影响公共案情。

### 5.3 任务执行与安全监控

任务必须由有权限的指挥人员创建或确认。志愿者接收本人任务后，可打开地图导航并在任务期间上报位置。系统只在必要时间、必要精度和必要人员范围内处理定位数据。

### 5.4 复盘与知识沉淀

案件结束后，聊天记录、任务、轨迹和结论先经过授权确认与脱敏，再生成时间线、复盘报告、经验标签和题库素材。未经审核的原始材料不得直接进入面向新人的知识库。

## 6. 公共案情最小结构

每份案情摘要至少应包含：

- 案件代号和当前状态；
- 生成/更新时间及负责审核人；
- 最后确认的信息；
- 最新有效线索及其核实状态；
- 待核实事项；
- 已排除或已失效方向；
- 当前重点和已分配任务的概况；
- 适用的安全提醒；
- “AI 辅助生成、以人工审核记录为准”的提示。

面向家属、志愿者和内部指挥的摘要应按权限生成不同视图，不能简单复用同一份全文。

## 7. 明确非目标

首阶段不做：

- 真实案件的无人值守自动指挥；
- 通过 AI 对人员身份或监控画面作确定性判断；
- 未经授权接入监控、运营商、医疗、公安或其他敏感系统；
- 面向公众开放完整案件详情、联系方式、病史或实时位置；
- 自动向高风险区域派遣人员；
- 使用未脱敏真实数据进行比赛演示、公开测试或模型训练；
- 把模型置信度直接等同于线索可信度。

## 8. 待确认事项

- MVP 最终采用响应式 Web、H5 还是小程序。
- FastAPI 与 Node.js 中的最终后端方案。
- 正式部署是否在现有数据库会话之外对接 OIDC/统一身份，以及组织/队伍模型、账号审批、密码找回和 MFA 流程。
- 定位回传频率、精度、保留期限和弱网策略。
- 地图、天气、路况和导航能力具体使用的 API 与配额。
- AI 服务、知识库与对象存储的部署区域和数据合规方案。
- 真实组织试用前所需的法律、伦理、安全和应急评审。
