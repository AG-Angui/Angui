# 安全与隐私边界

## 1. 安全目标

安归处理的信息可能直接关联老人安全、健康隐私、家庭联系方式、志愿者实时位置和搜救调度。即使 MVP 只使用模拟数据，也必须按照未来高敏感系统的基本边界设计，避免原型形成错误的权限习惯。

安全优先级：

1. 人身安全；
2. 防止敏感信息被未授权查看或扩散；
3. 防止错误信息被当作事实或任务依据；
4. 保证关键操作可追溯、可撤回和可复盘；
5. 在外部服务失败时保留人工协作能力。

## 2. 信息分级

| 等级 | 示例 | 默认可见范围 |
| --- | --- | --- |
| A 级：公开 | 防走失知识、队伍公开介绍、经批准的公开进展 | 公众或授权用户 |
| B 级：协作 | 本人任务、必要案情、已确认线索摘要 | 当前案件的相关志愿者 |
| C 级：内部 | 未核实线索、搜索方向、任务分配、人员状态 | 指挥人员和授权后台 |
| D 级：敏感 | 完整身份、照片、电话、病史、精确轨迹、监控资料、原始聊天 | 经特别授权的负责人；严格留痕 |

数据组合后可能升级。例如，模糊年龄与公开地点单独看风险较低，但与照片、病史和精确时间组合后应按 D 级处理。

## 3. 角色权限基线

### 家属/知情人

可查看本人提交内容、需要补充的问题和经确认的公开进展。不可查看内部线索、其他家庭信息、志愿者位置、搜索策略和未经核实的现场反馈。

### 指挥人员

按案件授权查看线索、任务、地图态势和必要的人员位置。发布案情、导出数据、改变权限、下发高风险任务等操作需要明确确认并记录。

### 志愿者

只查看本人任务、必要案情、导航位置和安全提醒。默认不查看其他志愿者完整轨迹、全量线索、完整病史和家属联系方式。

### 新人

只进入学习区和模拟案件。不得因“正在培训”而获得真实案件数据。

### 管理员/技术人员

管理配置、账号和运行状态不等于拥有全部业务数据权限。需要排障访问敏感数据时，应获得临时批准、限制范围并记录全过程。

## 4. 强制禁止项

- 未获授权接入或抓取公安、医疗、运营商、社区、监控平台或社交平台数据。
- 绕过登录、审批、审计或第三方服务的访问限制。
- 构建人脸识别、跨镜追踪或身份确认能力。
- 让 AI 自动认定线索、公开案情或派遣人员进入风险区域。
- 向家属、公众或无关志愿者展示实时人员位置。
- 把真实案件数据用于公开演示、压力测试、通用模型训练或未经批准的分析。
- 在源代码、日志、截图、Issue、提交信息或演示视频中暴露密钥和个人信息。

## 5. 定位与轨迹保护

- 只有参与任务且明确知情的志愿者才能启用位置回传。
- 界面应显示定位状态，并提供暂停/停止入口；任务结束后自动停止。
- 回传频率和精度按任务需要设置，避免持续采集高精度位置。
- 家属、公众和普通志愿者不能访问他人实时轨迹。
- 导出、回放和长期保存轨迹需要独立权限和理由。
- 轨迹保留期应尽可能短；复盘需要时优先保存简化、模糊化结果。
- 发现失联、异常偏离时只向有权限的指挥人员报警，不公开广播个人位置。

## 6. 应用安全基线

- 生产级密码使用可靠哈希算法；会话令牌短期有效并支持撤销。
- 所有对象执行服务端权限校验，防止通过修改 ID 访问其他案件。
- 对登录、上传、AI 调用、位置回传和导出设置速率限制与异常监测。
- 上传文件校验真实类型、大小和扩展名，使用随机存储名，并隔离处理。
- Web 输出进行编码，数据库使用参数化查询，避免 XSS 和注入。
- 跨域、Cookie、HTTPS、安全响应头按部署环境正确配置。
- 依赖锁定版本并定期扫描；高危漏洞发布前必须处理或形成书面风险接受。
- 备份加密并测试恢复；删除操作应覆盖主存储、缓存、索引和可控备份周期。

当前 MVP 已实现以下基础控制：

- 密码使用 Argon2id 哈希，哈希计算在阻塞线程池执行。
- 登录返回短期 Bearer 令牌，数据库只保存 SHA-256 令牌哈希；登出会立即撤销服务端会话。
- 会话默认有效期为 8 小时，可通过 `ANGUI_SESSION_TTL_HOURS` 在 1–168 小时范围配置。
- 登录失败同时按客户端 IP 和 IP+邮箱组合执行进程内限流；服务重启会清空计数，生产环境仍需共享限流存储和边缘防护。
- 所有案件和线索接口要求认证，并通过案件成员关系执行服务端授权。
- 无案件关系时返回与不存在一致的 `404`，减少通过 ID 枚举确认案件存在的风险。
- 志愿者详情不返回健康注意事项，只能看到已确认线索；家属只能看到已确认或本人提交的线索。
- 审计 actor 来自认证用户 ID，不再使用硬编码 Demo 身份。

当前尚未实现密码找回、MFA、管理员账号管理、账号审批、设备管理、全局会话查看、分布式限流和异常登录通知，因此仍不满足真实事件部署条件。

## 7. 日志与审计

应记录：登录与失败、权限变化、敏感详情访问、线索审核、摘要发布、任务分派、位置查看、导出、删除和 AI 结果审核。

不得记录：密码、令牌、完整电话、完整病史、原始聊天全文、精确轨迹、未处理附件内容和完整 AI 敏感提示。审计日志本身需要访问控制、防篡改与保留期限。

## 8. 第三方服务

调用 AI、地图、对象存储或监控服务前，需要确认：

- 数据发送到哪个服务、区域和账号；
- 服务是否保存输入，是否用于训练；
- 传输与存储加密方式；
- 子处理方、日志、保留和删除机制；
- API 密钥权限、配额和轮换机制；
- 服务不可用或条款变化时的退出方案。

默认不向第三方发送 D 级数据。确需发送时必须进行字段最小化、获得授权并完成专项评审。

## 9. 安全事件响应

发现疑似泄露、越权、错误公开、密钥暴露或危险任务时：

1. 立即停止相关发布、账号、密钥或自动流程，优先保护人员安全。
2. 保留必要证据，避免在公开群聊中继续传播敏感内容。
3. 通知项目安全负责人和有权限的现场负责人。
4. 确认影响的数据、人员、时间范围和第三方服务。
5. 按适用规则通知受影响方并修复问题。
6. 复盘根因，增加测试和控制措施后再恢复。

仓库尚未指定安全联系人。在建立公开仓库、真实部署或外部试用前，必须补充非公开的安全报告渠道和负责人。

## 10. 真实试用前置条件

在任何真实走失事件中使用前，至少完成：

- 法律、隐私和第三方条款评审；
- 威胁建模、渗透测试与权限测试；
- 数据保留/删除、授权和告知文本；
- 现场操作规程、培训、值守和紧急联系人；
- 外部服务中断、错误线索、定位失联和账号泄露演练；
- 明确由哪个具有资质的组织承担现场指挥责任。
